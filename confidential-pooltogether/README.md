# Confidential Pool implementation workspace

This workspace contains winner-selection reference contracts, mathematical models, deployment utilities, and the React product for the Zama Season 4 confidential PoolTogether bounty.

## Current release

The submission target is the FHE-random, Aave-backed Sepolia release:

- recurring confidential pool: `0xB967bD58dc9F4Ee10D8dcd6A1cBfA1bdDC1B9A88`;
- confidential aLINK wrapper: `0x78da50E954d2fC69C10688032c8c07D2ABC52750`;
- randomness: encrypted `FHE.randEuint64()` samples generated by the Zama runtime.

LINK is supplied to Aave V3, then aLINK is shielded as confidential `caLINK`. Aave backing growth is measured against issued confidential liabilities, and only the surplus can be minted into the pool's encrypted prize reserve. Winner selection maps each encrypted PoolTogether-style weight into a fixed `2^64` domain, samples encrypted Zama randomness, and compares the values without publishing the sample or winner bit.

See the final [FHE-random release record](../zama-context/08-bounty-pooltogether/fhe-random-sepolia-release.md). Its complete guarded lifecycle passed the strict Sepolia auditor.

## Privacy and verification boundary

Inside the pool, user balances, deposit and withdrawal amounts, per-user TWABs, winning zones, random thresholds, random samples, winner bits, reserve values, and payouts remain encrypted. Public data includes shield/redemption boundary amounts, Aave aggregate backing/yield, epoch timing, the KMS-proven aggregate denominator, account addresses, and action metadata.

Winner and non-winner claims use the same non-reverting public call shape. Only the participant receives ACL permission to decrypt the resulting payout handle.

## Release posture

This is a production-oriented demonstration, not audited production software. The Aave wrapper uses OpenZeppelin `SafeERC20` and `ReentrancyGuard`, immutable/one-time configuration, exact backing accounting, KMS-proof verification for public redemption, and adversarial tests. Full PoolTogether V5 tiering and liquidation auctions are intentionally outside the smallest correct confidential adaptation.
